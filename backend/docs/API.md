# API integration contract

Base URL: `http://localhost:5000/api` in development. JSON responses have `success`; errors have `message`, `requestId`, and optionally field-level `issues`. Dates use ISO strings. List responses include `total`, `page`, `limit` (default 20, maximum 100).

## Authentication

All patient, document and audit endpoints require the doctor session cookie. Send `credentials: 'include'` on frontend fetch calls. Login sets the cookie; it does not return a bearer token. Keep frontend and API on the same site for SameSite=Strict cookies (localhost ports are supported).

```ts
const response = await fetch('http://localhost:5000/api/auth/login', {
  method: 'POST',
  credentials: 'include',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ email, password }),
});
const result = await response.json();
if (!response.ok) throw new Error(result.message);
let csrfToken = result.csrfToken; // Keep in memory; refresh through GET /auth/me.
```

| Method | Endpoint       | Behavior                                                   |
| ------ | -------------- | ---------------------------------------------------------- |
| POST   | `/auth/login`  | Verify email/password; issue session cookie and CSRF token |
| GET    | `/auth/me`     | Return signed-in doctor and current CSRF token             |
| POST   | `/auth/logout` | Revoke session; requires `X-CSRF-Token`                    |

Login failures use a generic 401. Five failed passwords lock the known account for 15 minutes. IP limits also apply. Reloading the app should call `/auth/me`; a 401 should lead to the login screen.

## Patients

| Method | Endpoint                               | Behavior                                      |
| ------ | -------------------------------------- | --------------------------------------------- |
| POST   | `/patients`                            | Register patient and generate unique ID       |
| GET    | `/patients?search=...&page=1&limit=20` | Search name or Patient ID, case-insensitively |
| GET    | `/patients/:id`                        | Patient profile and stored document count     |
| PATCH  | `/patients/:id`                        | Update allowed profile fields                 |

Required creation payload:

```json
{
  "name": "Synthetic Patient Alpha",
  "dob": "1990-01-15",
  "gender": "Female",
  "phone": "0000000000"
}
```

Optional fields: `email`, `bloodGroup`, `address`, `insurance`, `nationalHealthId`, `emergencyContact`, `vitals`, `allergies`, `chronicConditions`, `notes`, `status`. Exact shapes are in `src/validators/schemas.ts`. Omit unknown optional values instead of sending placeholder data. The server rejects unexpected fields, including client-supplied `id`, `doctorId`, `age` and registration timestamps. Age and initials are display values to derive in the frontend. Nested PATCH fields merge with existing values. Send `null` for `bloodGroup` or `emergencyContact.phone` to clear those optional fields; clearing an entire optional object with `null` is not supported.

For a patient card, use the returned `id` and `name`. When clicked, fetch `/patients/:id` and `/documents?patientId=:id`; paginate documents to retrieve the complete record. The card and mobile layout remain frontend responsibilities.

## Documents

| Method | Endpoint                  | Behavior                                         |
| ------ | ------------------------- | ------------------------------------------------ |
| POST   | `/documents/upload`       | One multipart file plus metadata                 |
| GET    | `/documents`              | Paginated metadata; filters below                |
| GET    | `/documents/:id`          | Metadata for one document                        |
| GET    | `/documents/:id/view`     | Original PDF/image bytes with inline disposition |
| GET    | `/documents/:id/download` | Original bytes with attachment disposition       |

Upload metadata: `patientId`, `title`, `category`, `reportDate` are required. `subType` and `notes` are optional. `reportDate` is a valid, non-future `YYYY-MM-DD`; `uploadedAt` is generated by the server. The multipart file field is named `file`.

Categories: `Medical History`, `Laboratory Report`, `Imaging Report`, `Prescription`, `Pharmacy Bill`, `Hospital Invoice`, `Discharge Summary`. Use `subType` for X-ray, CT or MRI. DICOM is not supported.

```ts
const form = new FormData();
form.set('patientId', patientId);
form.set('title', 'Synthetic laboratory report');
form.set('category', 'Laboratory Report');
form.set('reportDate', '2020-05-12');
form.set('file', file);
const response = await fetch('http://localhost:5000/api/documents/upload', {
  method: 'POST',
  credentials: 'include',
  headers: { 'X-CSRF-Token': csrfToken },
  body: form, // Let the browser set the multipart Content-Type boundary.
});
```

List filters: `patientId`, `category`, `from`, `to`, `page`, `limit`. Date range filters apply to report date, inclusive. Results are ordered by report date descending, then upload time. Metadata includes ID, patient ID, title/category, report/upload dates, original filename, MIME type, byte size and SHA-256 checksum. Storage keys and provider URLs are never exposed.

View/download responses use `Cache-Control: no-store`. Use an authenticated fetch to obtain a Blob for display/download; release object URLs after use. Direct iframe embedding is blocked by the API's security headers. Only allow PDF, JPG and PNG in the upload UI, matching the API's configured limit (default 10 MB).

## Audit events

`DELETE /documents/:id` permanently removes an owned document's stored file and metadata.
`DELETE /patients/:id` permanently removes an owned patient and all their documents/files.
Both require the session cookie and `X-CSRF-Token`, return `{ "success": true }`, and retain audit history (`DOCUMENT_DELETE` or `PATIENT_DELETE`). The frontend asks for confirmation before sending either request.

Storage cleanup happens before metadata removal. A failed patient deletion may be partially complete; retry the patient DELETE to finish. Once deletion starts, uploads and profile edits are blocked, but the patient remains discoverable for retry until cleanup succeeds. Storage, MongoDB and audit writes are not one atomic transaction. Provider backups follow the provider's separate retention settings; this endpoint does not purge backups.

`GET /audit?action=DOCUMENT_DOWNLOAD&patientId=PT-2026-001&page=1&limit=20` returns persisted events. No CSV export, update or delete endpoint is included. Entries contain actor ID, action, resource/patient IDs, outcome (`attempt`, `success`, `denied`), request ID, IP and occurrence time. Patient names, passwords, tokens and request bodies are excluded.

## Frontend integration

The frontend now uses `src/api/client.ts` for cookie-authenticated requests, CSRF headers, JSON errors and protected file fetches. `AuthContext.tsx` restores the session with `/auth/me`, and clears the authenticated workspace on session expiry. `PatientRecordContext.tsx` implements create/update/upload/download operations; each page loads paginated data with `useApiQuery`. Old browser caches are removed, and prototype mock data is no longer imported by the running application.

The upload form retrieves the configured limit from authenticated `GET /config` (`maxFileSizeMb`), supports report dates and all seven categories, and sends the actual selected file. The document viewer renders authorized Blob URLs and revokes them on unmount. The patient directory and global search call the backend. Unsupported simulated features (public sharing, fake medical findings, CSV exports, fabricated health identifiers and security certification badges) are not shown.

For JSON POST/PATCH requests set `Content-Type: application/json`, `credentials: 'include'`, and `X-CSRF-Token`. Do not automatically retry failed writes: audit completion and database writes are not transactional in this version.

Common status codes: 400 invalid input; 401 login required/failed; 403 CSRF/origin rejected; 404 record absent or not owned by the doctor; 409 identifier conflict; 413 size limit; 415 unsupported/mismatched file; 426 HTTPS required; 429 rate limit; 500 internal failure. Include `requestId` when investigating errors.
